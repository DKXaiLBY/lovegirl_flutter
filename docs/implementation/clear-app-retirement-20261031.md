# 六项功能退出：源代码进度与兼容边界

用户确认取消：每日一问、慢信、爱心豆、签到、成就、愿望兑换券。历史数据保留；本记录不代表线上接口已停用或新客户端已发布。

## 前台源代码已处理

- 首页移除问答卡与前后台恢复时的问答刷新，根Provider不再注册每日一问。
- 回忆移除问答与慢信；我们移除积分/签到、成就和兑换券，并停止相关数据请求。
- 首页移除签到状态请求及签到操作，保留待办、厨房、旅行、财务和纪念日解析。
- 旧问答、慢信、成就通知仅显示停用说明，不再打开旧功能，也不能通过旧载荷的订单ID进入其他业务。
- 月报与年报忽略旧响应中的退役计数、亮点及文案，不删除原记录。
- `tools/audit_retired_features.py`从真实入口遍历项目静态依赖：当前100个可达库中没有退役页面、Provider或已列出的退役API调用。旧源码和兼容模型未删除，但不再被主程序引用。

新增8项客户端回归已从失败变为通过。静态审计不代替真机功能/视觉验收，也不证明服务端已经完成退出。

## 服务端准备中的修改（未部署）

live预检确认目标文件与已验证备份一致。实际运行的helper比本地旧副本多了烹饪成就等内容，补丁因此使用live基底，保留有效的共用能力。

- `server_fixes/retired_features.js`提供经过原认证中间件的HTTP410响应，覆盖积分/签到、成就、慢信、兑换券及问答today/answer/history。
- `server_fixes/app.js`提前挂载拦截并退出旧路由加载。独立的“每日一言” `/api/daily`和`/quote`不属于问答，继续保留。
- 兼容的奖励导出不再读取/写入奖励表；发放和扣减返回null，成就返回空集合，签到进度返回0。记账加密、时光轴、伴侣查询与私密经期辅助保留。
- 没有迁移、删除或清空生产表，补丁没有写入线上App目录。

6项奖励副作用隔离测试通过；5项路由测试使用实际服务端Node18/Express依赖，仅在内存加载补丁，覆盖50次隔离HTTP请求组合。不同方法/大小写/尾斜线/查询参数不能重开退役业务；未认证仍返回401；保留的每日一言与厨房路径可达。

测试为`server_fixes/tests/rewards_retirement.test.js`及`retired_features.test.js`。日志在本地备份目录`reward-retirement-before.log`、`retirement-server-tests-all.log`。测试没有连接生产数据库或向生产业务接口提交记录。

2. 服务端首页和报告仍有旧奖励/问答/慢信统计查询，需要按真实业务和旧字段兼容规则处理。
3. 旧客户端升级表现、真实业务保存/完成路径及停止奖励后的数据保护检查尚未完成。
4. 当前代码尚未形成完整验收的发布单元，正式版本仍为4.4.2+187。
5. UI参考图还原、其他页面和旅行准备保持原目标，不能被功能精简替代。

正式部署需再次核对live，保留已验证备份；发布单元可用前不先切换半套退役逻辑。
