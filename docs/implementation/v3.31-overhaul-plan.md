### 第二批：相册拍立得收集本（参考图设计语言，用户已给 2 张参考图）

参考图提炼的 6 条设计语言（App 现状与它的契合点）：
1. **纸感背景**：灰白/暖纸底带细微纹理（App 已有暖纸底 token，加纹理素材）
2. **拍立得相纸**：方形照片+白框+宽底边，**底边手写体日期**（灵魂细节；需引入手写字体如"开心体/站酷快乐体"或 Google Fonts 手写中文字体，license 需确认）
3. **故事背卡**：每张照片背后一段文字——点击照片**翻转动画**：正面照片+手写日期，背面胶片黑底白字的故事（相册 photos.description 字段现成；支持编辑）
4. **层叠与随机倾斜**：±2° 确定性伪随机（按照片 id 哈希，不重排不闪烁），部分卡片底部露出下一张的边（层叠暗示可翻）
5. **收集本仪式感**：底部居中"+"上传；空态"添加你的第一个故事"+引导箭头（参考图 1）
6. **胶片感**（可选开关）：轻降饱和+微暗角（ColorFilter 实现，注意列表性能——只对可见卡片生效）

落地范围：**云端相册浏览视图**整体改造为拍立得收集本；批量选择模式与拍立得兼容（多选时取消旋转胶带，切换为勾选态）。翻页书（flipbook）保持现状另做顺滑度专项（见第三批）。

## 二、第一性原理：四个元病灶（所有 13 项的收敛）

1. **契约无验证**：URL/字段名错位（上传 404）→ 建"接口契约清单"+真机上传冒烟
2. **错误反馈链路断裂**：服务器真话被 `e.toString().contains()` 吞掉 → 统一 `extractServerMessage`
3. **验收 = 代码能跑，而非用户能懂**：底部 1 秒 snackbar、星图拉伸 → 交付定义升级（交互自测表）
4. **改动无回归网**：全屏化改坏投影、清理误删绑定 → 冒烟清单 + 测试数据一律标记（test_ 前缀）+ 清理前二次确认

## 三、系统性排查方法论（回应"我不想一个个排查"）

发布前固定四道闸（每版执行，写入交付流程）：
1. **静态闸**：analyze 0 问题 + 孤儿页/死接线检测脚本输出为空
2. **接口闸**：App 所有调用的接口清单 × 服务器路由清单对账（本次上传 404 就是这个没对）
3. **真机遍历闸**：交互点总表逐点点击（adb 脚本辅助），含双角色/深浅色/键盘/断网
4. **录像审查闸**：adb screenrecord 录主流程 → 拉回本地逐帧抽查（按钮响应、转场、加载态）→ 问题列清单 → 修复 → 对抗性审查复验 → 循环直到清单清零
辅助：服务器日志（docker logs）+ App 内 LogService 页面（已有）+ logcat 过滤 Flutter 异常
