**二、整体视觉规则**

- 延续此前已获认可的大张实体相纸：照片占主体，纸张有厚度、纹理、照片窗内凹和柔和投影。
- 相纸和票根使用实体材料表现；工具栏与弹层使用克制的磨砂玻璃。主按钮保持不透明黑底白字，文字优先保证对比度。
- 相机保留金属快门等触感细节，机身装饰不挤占大部分取景空间。
- 不将三个模块变成相同的卡片列表：照片以单张浏览为主，票根以模板与作品画布为主，旅行以地图和可收放行程面板为主。
- 地图沿用圆周旅迹参考中的浅色底图、清晰路线和编号层级。路线使用功能性青蓝色，不据此更改全App主题。
- 相纸/票面颜色与照片滤镜可有丰富变化；外围导航、字体和主操作保持中性一致。
- 所有纸纹、投影、玻璃和过渡需在荣耀畅玩20实测后确定实现方式；静态图不能证明实时折射效果或设备帧率。

**七、图外必须一起实现的操作规则**

| 状态或操作 | 行为 |
|---|---|
| 进入制作 | 可从相册独立进入，也可从某次旅行选择照片进入；后者保留旅行关联 |
| 存草稿 | 不发布给另一人；保存后给明确反馈；本期至少保证当前设备退出/重启后可恢复，跨设备草稿同步不作为新增承诺 |
| 完成并收藏 | 写入成品成功后再展示双方可见状态；失败保留草稿和所有输入，不显示假成功 |
| 继续编辑 | 从作品进入个人制作草稿，完成后更新成品；不将未完成修改即时共享 |
| 导出图片 | 只导出作品画布，不含工具条、输入框、选中框；文件保存与相册写入分别核验和反馈 |
| 删除 | 先确认，取消保持原记录；成功后同步清单、地图、计数和路段；失败保留记录 |
| 地图排序 | 长按手柄再拖动，避免与面板/清单滚动混淆；交通方式继承规则在实现中明确，不能沿用错误旧路段 |
| 行程冲突 | 保留本次未提交修改；提示对方已更新，加载最新后继续；不无声覆盖，也不伪造实时共同编辑 |
| 加载/保存中 | 给明确进度或状态，防重复提交；可恢复失败后重试 |
| 断网 | 已有输入和个人草稿保持；需要联网的保存/路线请求给明确错误，恢复后可重试 |
| 深色与窄屏 | 核心字段、按钮、纸面文字仍清晰；最终需以真机画面校验 |

以上为将已选方案具体化后的交互约定，一并供本次视觉审阅。图片未覆盖每一个错误弹窗、草稿列表、权限提示或深色页面，不将它们从后续验收范围中删去。
