# LoveGirl 本轮统一目标与验收标准

日期：2026-07-18

## 统一目标

在不引入新技术栈的前提下，完成本轮 LoveGirl 核心修复与重构收口：

1. 补齐 `server_fixes/` 缺失的基础后端依赖与核心路由，保证服务可启动。
2. 修复首页、投喂站、旅行地图、我的页的主链路问题，避免明显的崩溃、乱码、英文残留和布局溢出。
3. 落实已确认的票根系 UI 方向，让首页与旅行、投喂等核心页面的视觉语言一致。
4. 把旅行地图切到高德 Android 原生地图路线，不再继续维护 `flutter_map + 高德瓦片` 方案。
5. 把当前结果推进到“可继续真机验收与发布准备”的状态，而不是停留在静态页面改图。

## 当前边界

本轮先聚焦四条主线：

1. 首页
2. 投喂站
3. 旅行地图
4. 我的页

以下工作不在本轮强行扩张：

1. iOS 地图适配
2. 高德导航 SDK 二阶段完整接入
3. 全模块 UI 一次性彻底翻新
4. 所有历史页面的顺手式重构

## 已确认的实现方向

### 1. UI 方向

- 采用“回忆票根 / 专属菜单”视觉语言。
- 首页保留票根式信息组织，但所有用户可见文案优先中文化。
- 旅行地图预览使用票根化路线卡与地点详情，真地图只在需要查路和定位时进入。
- 投喂站保持“像真的在下单”的流程感，不做办公软件式界面。

### 2. 地图方案

- 主地图使用项目已有的 `amap_flutter_map`。
- 路线、天气、POI、地理编码走高德 Web 服务，由后端代理。
- Flutter 前端不暴露 Web 服务 Key。
- 真地图模式优先保证稳定性和可退回，而不是一次性堆满功能。

### 3. 可添加性原则

为了后续继续加功能，本轮改动遵守下面三条：

1. 不把首页、旅行、投喂的展示逻辑继续塞进单个巨型组件里。
2. 能落在 Provider / API / 视图模型边界上的数据，不直接写死在 Widget 里。
3. 所有新增后端模块都保持独立路由文件，避免后续继续回到“大一统入口文件”。

## 验收标准

### A. 后端基线

- `server_fixes/app.js` 可以在本地正常 `require` 并启动。
- 缺失的基础依赖不再导致服务直接起不来。
- 首页、用户、聊天、天气等本轮依赖的关键接口具备最小可运行能力。

### B. 首页

- 首页核心模块以中文显示。
- 天气卡片不再出现体感温度溢出边框的问题。
- 首页错误提示文案对用户友好，不直接暴露底层异常信息。

### C. 投喂站

- 投喂站主界面、商品卡、订单态继续保持票根/菜单方向。
- 用户可见文案不出现明显乱码。
- 核心数据加载失败时有明确提示，不是静默空白。

### D. 旅行地图

- 旅行预览页和票根页不再出现明显英文残留。
- 真地图入口在 Dart 层有平台与装载容错，不应因明显前置条件问题直接崩溃。
- 地图标记信息、路线卡、票根标题文案统一到当前 UI 方向。
- 真地图模式即使加载慢，也要能给出等待、重试、回退路径。

### E. 工程质量

- 改动文件通过 `flutter analyze` 或 `node -c` 的对应检查。
- 不因为修 UI 顺手引入无关大改。
- 不构建正式 APK，直到核心链路经过进一步真机验收。

## 本轮完成定义

满足下面条件，才算本轮目标进入“可发布准备”：

1. 后端基线可启动。
2. 首页 / 投喂站 / 旅行 / 我的页的高可见问题完成一轮清理。
3. 高德真地图模式具备足够的源码级容错与失败回退。
4. 关键文件分析通过。
5. 剩余风险被明确记录，而不是假装不存在。

## 剩余风险记录

1. 高德真地图的最终稳定性仍需要 Android 真机验证，当前不能只依赖静态分析和编译通过。
2. 旧页面中仍可能存在历史风格遗留，但不应继续阻断本轮四条主线。
3. 若服务器真实数据库结构与本地假设不一致，仍需上线前再做一次联调核对。
