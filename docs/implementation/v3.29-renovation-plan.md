## 二、走查发现的问题清单

### 孤儿页面（代码完整、无任何导航入口）
1. **成就页** `achievements_screen.dart` —— 我的页"12 成就"是死数字，点不进去；且成就标题全是英文（"First travel check-in"）
2. **心情页** `mood_screen.dart` —— 有 6 条历史数据却找不到门
3. **聊天页** `chat_screen.dart` —— 无入口（建议保持，微信覆盖，理由见下）
4. **倒数日** `countdown_screen.dart + countdown_form.dart` —— 整个模块无入口

### 功能性问题
5. **时光轴 0 条**：服务器早有 `createTimelineEvent` 基建（旅行打卡在用），但各模块不往里写、App 也没有"自动沉淀"逻辑 → 回忆总入口永远是空的
6. **爱心豆只有收入感**：流水清一色 +5/+10；兑换券刚上线还没形成消费心智
7. **首页没有"对方"**：五张卡全是功能入口（厨房/待办/一问/回忆/旅行/账本），打开首页看不到 TA 最近做了什么——女生视角走查时的第一诉求
8. **经期关怀单向缺失**：女友记经期，男友端完全无感知（无"特殊时期多关心"类提示；隐私上应只给提示不给细节）
9. 设置页"导出数据"= 开发中占位
10. 开发者角色切换对健康页无效（有意设计，`isOriginalGirl` 防误拉私密数据，保留并补注释即可）

## 三、第一性原理体检

情侣 App 剥掉所有功能，只剩五个根本任务：

| 根本任务 | 现状评分 | 短板 |
|---|---|---|
| 1. 记录共同生活（沉淀资产） | ★★☆ | 旅行/相册/慢信强，但**"吃"这条线完全缺失**（做饭是你们的高频共同生活）；时光轴该是沉淀出口却是 0 |
| 2. 表达与感知爱意 | ★★★ | 兑换券/一问很好；但首页看不见"TA 的存在" |
| 3. 低成本日常仪式 | ★★★★ | 签到+一问成立（签到天天在用） |
| 4. 数据资产复利 | ★★☆ | 数据都有，但散在各处没有"越用越值钱"的呈现（年度报告一年才一次） |
| 5. 隐私与安全感 | ★★★★★ | 自托管+经期隔离，是同类产品没有的优势 |

**核心洞察：不做新功能清单，做"接线"——把已投入的开发量接活，把"吃"这条缺失的生活主线补上。**

## 五、美食手账——三个候选架构（待用户四问后定稿）

### 方案 A：独立手账（最轻）
新模块"美食手账"，入口在回忆与管理。纯记录流，不碰厨房。
- 优点：零耦合、最快（1 天）；缺点：和厨房两张皮，菜单依旧 0 使用

### 方案 B：手账 + 菜单打通（推荐）
在 A 之上：记录新菜时可勾选"挂上 TA 的点单菜单"→ 写入 kitchen_dishes；点单完成订单时可引导"记录这次的成品"→ 生成 cooking_log。
- 优点：把 0 使用的厨房变成手账的下游；"她做的菜→收录→被点单→再复刻"形成故事线
- 缺点：多 1 天工作量

### 方案 C：厨房整体改造（最重）
把情侣厨房页重构成"她的小厨房"：手账为主视图，点单收进次级 tab。
- 优点：一步到位；缺点：推翻 v3.23 刚做的页，改动面大，风险高

**推荐 B。**

### 数据模型草案（B 方案）
```sql
CREATE TABLE cooking_logs (
  id INT AUTO_INCREMENT PRIMARY KEY,
  chef_id INT NOT NULL,               -- 谁做的
  title VARCHAR(100) NOT NULL,        -- 菜名
  emoji VARCHAR(16) DEFAULT '🍳',
  photo_url VARCHAR(500),             -- 成品照
  is_new TINYINT(1) DEFAULT 1,        -- 新做 vs 复刻
  story VARCHAR(1000),                -- 一句话/小故事
  difficulty TINYINT NULL,            -- 掌勺自评难度 1-5
  eater_id INT NULL,                  -- 品尝人
  eater_rating TINYINT NULL,          -- 品尝评分 1-5
  eater_comment VARCHAR(300) NULL,    -- 品尝留言
  cooked_at DATE NOT NULL,
  dish_id INT NULL,                   -- 挂上菜单后回链 kitchen_dishes
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  KEY idx_chef (chef_id, cooked_at)
);
```
通知：新菜上账（通知对方去评分）→ 品尝评分（通知掌勺"TA 打了分"）→ 挂菜单成功。时光轴自动写事件（source_module='cooking'）。年度报告聚合 `cooking_logs`。
