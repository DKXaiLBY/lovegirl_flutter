## 一、本次问题的诊断结论

**复现结果：未复现。** 真机（荣耀 ARMJ9X1519G20642）完整走了一遍：我的页 → 美食手账 → 点"记一道" FAB → 表单弹出 → 填菜名 → "收进手账" → 成功入册（有截图证据链）。FAB、表单、提交、图鉴点亮全链路可用。

但用户确实遇到了，两个候选根因按可能性排序：

### 候选 A（最可能）：入口可发现性/信息架构问题
想"记录做的新食物"，直觉是去**情侣厨房**页——但厨房页里**没有任何记录入口**，"美食手账"藏在**我的页 → 回忆与管理**两层深。如果用户进的是厨房页，看到的点单流程（0 使用的旧功能）里没有"记一道"，感知就是"没法记录/按钮没法用"。
→ 修法：厨房页顶部加"美食手账"入口；首页"情侣厨房"卡的文案引导。

### 候选 B：点击偶发无响应
我在自测中两次观察到 FAB"点了没反应"（第三次才成功），本次复现又观察到 **adb 切 tab 的 tap 被丢弃**。可能与底部手势条区域（FAB 中心距屏底仅 94px）、或首帧渲染未完成时的点击有关。真机手指点击是否复现待确认。
→ 修法：FAB 上移避开手势区（安全边距）；点击热区扩大；加按下涟漪反馈让"没响应"可见。

**根因分类学（审计按此 5 类逐项过）**
- A 类：功能写完了，页面没有任何入口（孤儿页）
- B 类：回调/弹窗写了，没有任何控件触发它（死接线）
- C 类：时序问题——状态未就绪时按钮误判、异步回来 setState、键盘顶位移
- D 类：视觉/反馈缺失——禁用态无解释、点击无涟漪、用户不知道能不能点
- E 类：可发现性/信息架构——入口过深、场景页缺动作入口、术语不一致

## 三、审计方法：三道工序

### 工序一：代码静态盘点（半天）
自动化脚本 + 人工核对，产出**《交互点总表》**：
- 提取所有交互控件：`onPressed:` / `onTap:` / `GestureDetector` / `InkWell` / `LoveMenuRow` / `Switch` / `TextField` / `FloatingActionButton`，记录所在页面、回调函数名
- **B 类检测**：每个 `void _showXxx` / 私有回调方法必须有至少一处引用（上次记账 bug 就是这个模式）
- **A 类检测**：每个 `*Screen` 类必须有至少一处 `Navigator.push` 引用（孤儿页检测）
- 产出表格：页面 × 控件 × 回调 × 入口路径 × 初判风险

### 工序二：真机逐点遍历（1 天）
按总表在真机上逐个真实点击，每点必留证据（点击前后截图对比）：
- 覆盖：全部主 tab + 全部子页 + 全部弹窗/表单的提交与取消
- **双视角**：男友端一遍、开发者模式切女友端一遍（健康页等）
- **双主题**：深色模式过一遍关键交互
- **场景态**：键盘弹出时底部按钮是否可点、无网络时的按钮反馈、空态页的按钮
- 重点专项：**所有 bottom-right FAB**（美食手账/兑换券/慢信 3 处同款）做"贴边可点性"专项（连点 5 次必须 5 次响应）
- 产出：勾选表（通过/失败/截图编号）

### 工序三：修复 + 回归沉淀（半天~1 天视问题数量）
- 按严重度修复：点不动 > 点了没反馈 > 可发现性差 > 文案
- 每修一个，把该交互点写进**《发布前冒烟清单》**（固定 20 条主流程，每版发布前必跑）
- 产出：修复 commit（独立 tag）+ 冒烟清单定稿

## 四、预防机制（写进以后的交付流程，防止复发）

1. **交付定义升级**：以后每做一个新页面，交付物必须包含"本页交互点自测表"（每个按钮点过、截图）——不再允许"代码能跑就算完成"
2. **孤儿/死接线检测进发布前检查**：工序一的两个检测脚本化，每版发布前跑一遍，输出必须为空
3. **设计规范补充两条**（写进 DESIGN_SYSTEM）：
   - 推入式全屏页的 FAB 必须避开底部手势区（上移安全边距），或改用页内顶栏按钮
   - 核心动作必须在**场景页内**有入口（记录做饭的入口要在厨房页，不能只在我的页）
4. **验收口径改变**：我自测时"多点几次成功了"不算通过——一次点击必须响应，且关键按钮要连点 3 次验证稳定性
