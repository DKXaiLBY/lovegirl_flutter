# LoveGirl 后半程执行包（M6-M12）

更新时间：2026-07-17
适用阶段：在 `M1-M5` 已进入稳定推进后，继续完成全量重构时使用

## 1. 这份文档的定位

前面的执行包已经覆盖：

- `M1-M3`：基线清理、设计系统、首页重构
- `M4-M5`：投喂站、旅行地图

这份文档补的是后半程，让这轮 LoveGirl 重构从“核心页成形”继续走到“全量收口、可审查、可真机验收、可发布”。

它覆盖的范围是：

- `M6 我的页重构`
- `M7 Life 域收口`
- `M8 Memory 域收口`
- `M9 联动与爱心豆`
- `M10 后端统一与迁移`
- `M11 对抗式审查`
- `M12 真机验收与发布`

## 2. 适用前提

建议在下面这些条件大体成立后，再进入本执行包：

- `M1` 已完成结构降噪
- `M2` 已完成设计系统统一
- `M3` 首页已形成视觉母版
- `M4` 投喂站主链路已成立
- `M5` 旅行地图主链路已成立

如果前面的母版页和主链路都还没站稳，后半程容易变成“给半成品继续叠功能”。

## 3. 总体原则

### 3.1 后半程不是加散功能，而是收成体系

这几个阶段的重点不是“再多做几个页”，而是：

- 让剩余模块知道自己归哪
- 让联动开始真正工作
- 让前后端结构开始对齐
- 让发布前的风险提前暴露

### 3.2 优先保证结构闭环，再追求补满细枝末节

后半程的优先级应当始终是：

1. 模块职责清楚
2. 联动有来源和落点
3. 数据与安全不回退
4. 真机与发布路径可验证
5. 体验细节继续打磨

### 3.3 审查和发布不是结尾动作，而是从现在开始倒推

后半程每一步都要带着发布视角看：

- 数据会不会丢
- 路由会不会越改越乱
- 真机上会不会崩
- 新版本能不能真的更新
