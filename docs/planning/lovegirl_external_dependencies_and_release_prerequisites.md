# LoveGirl 外部依赖与发布前置条件

更新时间：2026-07-17
适用阶段：方案确认阶段（当前不写业务代码）

## 1. 文档目的

这份文档只关心“代码之外，后续要让 LoveGirl 真正可验收、可发布，还缺什么外部条件”。

它主要覆盖：

- 高德相关依赖
- 服务器与环境变量
- Android 发布信息
- 更新链路前置条件
- 真机验收前置条件

## 2. 高德相关前置条件

## 2.1 Android 地图 SDK Key

用途：

- 旅行地图真地图模式

要求：

- 绑定 LoveGirl Android 包名
- 同时确认 debug / release 使用场景
- 正式发布前必须确认 release 证书 SHA1 匹配

发布前需要确认：

- Key 已创建
- 包名正确
- SHA1 正确

## 2.2 Android 导航 SDK Key

用途：

- 后续接入原生导航能力

说明：

- 本轮允许先做路线预览，再接真实导航
- 但如果要把导航列入本轮可发布能力，Key 必须提前准备

发布前需要确认：

- Key 已创建
- 导航 SDK 所需隐私初始化方案已准备

## 2.3 高德 Web 服务 Key

用途：

- POI 搜索
- 地理编码 / 逆地理编码
- 路线规划
- 天气查询

要求：

- 不放进 Flutter 前端
- 放进后端环境变量
- 与服务器部署环境一致

发布前需要确认：

- Key 已创建
- 已写入服务器 `.env`
- 后端代理接口能正常返回

## 3. Android 端发布前置条件

## 3.1 包名与签名信息

需要确认：

- 当前正式包名
- debug SHA1
- release SHA1
- 签名文件与密码存放位置

原因：

- 高德 Android SDK 与正式发布都依赖这些信息

## 3.2 版本号与构建号

需要确认：

- 下一次发布的 `versionName`
- 下一次发布的 `versionCode`
- 服务端版本接口需要返回的新版本信息

原因：

- 客户端更新链路不能只更新 APK 文件，还要和版本检查逻辑一致

## 3.3 真机设备

至少需要准备：

- 一台可安装调试包的 Android 真机

重点用途：

- 验证地图
- 验证天气
- 验证页面真实布局
- 验证通知与更新链路

## 4. 服务器与后端前置条件

## 4.1 服务器连接与部署位置

已知背景：

- 服务器地址：`47.121.119.191`
- 当前后端涉及 Docker Compose 和服务端部署目录

后续发布前需要确认：

- 当前线上运行目录
- 待部署代码目录
- 更新 APK 的静态资源目录
- 版本接口读取的 APK 地址

## 4.2 服务器环境变量

至少应确认下面几类变量：

- 数据库连接
- JWT / 认证密钥
- 高德 Web 服务 Key
- CORS 来源配置
- 文件上传路径
- 版本发布目录或公开下载地址

发布前需要确认：

- 变量已配置
- 新增变量不会覆盖旧服务正常运行

## 4.3 数据库迁移执行条件

需要确认：

- 迁移脚本执行顺序
- 是否需要备份线上数据库
- 是否允许停机窗口
- 新表与旧表兼容策略

原因：

- 投喂 v2、爱心豆、旅行扩展、纪念日与相册整合，都可能涉及结构调整

## 5. 推送与通知前置条件

本轮如果要把催单改成真实提醒，发布前需要确认：

- Android 端通知权限申请链路
- 本地通知或远程推送实际方案
- 服务器是否需要持久化通知记录
- 通知失败时是否有补偿记录

说明：

- 如果本轮只做到本地提醒，也要明确边界
- 如果做到远程推送，必须在发布前跑通一次真实触发链路

## 6. 版本更新链路前置条件

需要确认：

- 客户端如何检查新版本
- 服务端版本接口字段格式
- APK 实际存放路径
- 下载地址是否稳定
- 更新弹窗文案是否中文正常

发布前必须验证：

- 老版本能检测到新版本
- 新版本链接能下载
- 下载后可正常安装

## 7. 真机验收前置条件

在开始最终真机验收前，应至少准备好：

- 高德相关 Key
- 正确签名信息
- 真机设备
- 测试账号
- 一组可用的旅行地点数据
- 一组可用的投喂商品与订单数据
- 一组纪念日 / 课程 / 待办示例数据

原因：

- 没有数据就无法判断 UI、联动和运行态是不是真的成立

## 8. 发布阻断项

在下面这些条件没有确认前，不允许发布：

- 高德地图 Key 与签名信息正确
- 后端环境变量完整
- 版本号与更新接口一致
- 新 APK 下载地址可用
- 真机地图不崩
- 真机核心页布局正常
- 投喂站主流程可走通
- 至少完成一轮发布前总核查

## 9. 当前阶段结论

截至 2026 年 7 月 17 日，这些外部依赖并不能靠代码自动解决。

所以这份文档的作用是：

- 提前把“代码外的发布条件”列清楚
- 避免后期出现“功能做完了却发不了”的情况
