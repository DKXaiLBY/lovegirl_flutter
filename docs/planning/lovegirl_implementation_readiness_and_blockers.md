## 1. 文档目的

这份文档专门回答一句话：

“如果现在开始真正写代码，哪些事可以立刻做，哪些事会被外部条件卡住？”

它的作用是把“准备开工”拆成三类状态：

- 现在就能做
- 做到一半前必须补条件
- 不补条件就不能完成最终发布

## 2. 状态定义

### Ready Now

定义：

- 当前仓库和现有文档已经足够支撑开工
- 不需要再等你补新信息

### Ready With External Input

定义：

- 可以先做一部分
- 但做到关键节点前，需要外部信息或环境条件

### Release Blocker

定义：

- 不影响前期重构推进
- 但会直接阻断真机验收或正式发布

## 5. Ready With External Input：做到关键处前需要补条件

这些事情可以先推进，但在某些节点前必须补齐外部条件。

## 5.1 高德地图完整能力

- 地图页面结构
- 浮层控件

## 5.2 高德导航能力

## 5.3 服务器接口补全

可以先做：

## 5.4 更新链路最终打通

- Android 端真实通知权限链路验证

## 6. Release Blocker：不解决就不能发版的事项

下面这些事情如果不解决，不影响早期重构推进，但会直接阻断最终目标。

## 6.1 高德真地图真机验证

阻断原因：

- 你要求旅行地图必须可用
- 这件事不能只靠编译通过证明

## 6.2 服务器环境与 Key 配置

阻断原因：

- 高德 Web 服务
- 版本更新接口
- 部分部署能力

都依赖服务端配置

## 6.3 签名与发布信息

阻断原因：

- 高德 Android Key 和正式发布都依赖正确签名信息

## 6.4 更新链路真实验证

阻断原因：

- 你的目标不是只打一个 APK
- 而是要“发布新版本后可以在手机里更新”

## 6.5 对抗式审查 P0 清零

阻断原因：

- 在投喂、地图、权限、上传、安全这些地方留 P0 缺口，就不能发布

## 7. 当前最重要的判断

如果现在问：

“能不能开始实现？”

答案是：

**可以，而且应该开始。**

如果现在问：

“能不能不依赖任何外部条件，一路做到最终发布？”

答案是：

**不能。**

更准确地说：

- 可以先推进到很深的实现阶段
- 但发布前一定会卡在真机、高德、服务器、签名、更新链路这些外部条件上

## 8. 推荐的推进策略

最合理的做法不是等所有条件齐了再开工，而是：

1. 先做 `Ready Now`
2. 同步准备 `Ready With External Input`
3. 到发布前集中击穿 `Release Blocker`

这个顺序能最大化减少等待成本。

## 9. 当前阶段结论

截至 **2026-07-17**，LoveGirl 的当前状态不是“还不能做”，而是：

- 方案足够了
- 基线清理和 UI 重构可以立刻开干
- 最终发布仍然受外部条件制约

所以当前阶段最准确的结论是：

**可以开始实现，但不能假装外部依赖不存在。**
