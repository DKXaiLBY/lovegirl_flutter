# LoveGirl M1-M12 主控交付清单

更新时间：2026-07-17
适用阶段：从方案切入实现后，用于总控每个里程碑的进入条件、交付证据与退出门槛

## 1. 这份文档的定位

前面的文档已经回答了：

- 这轮重构要做什么
- 每个模块怎么收口
- 每个阶段怎么拆任务
- 风险、依赖、安全和发布门槛是什么

这份文档再往前走一步，专门做总控用途。

它只回答三个问题：

1. 每个里程碑开始前要满足什么条件
2. 每个里程碑结束时必须留下什么证据
3. 什么情况下允许进入下一个里程碑

它不是替代执行包，而是把 `M1-M12` 串成一条可以“按门槛推进”的主控清单。

## 3. 主控原则

### 3.1 没有证据，不算完成

任何阶段都不能只凭“看起来差不多”过关。

至少要有下面几类证据中的一种或多种：

- 修改后的文件
- 文档化的责任表 / 契约表 / 矩阵
- `flutter analyze` / 编译结果
- 模拟器或真机截图
- 真机验收记录
- 审查报告
- 部署记录

### 3.2 退出门槛比进入门槛更重要

很多阶段都可以开始，但不能稀里糊涂往下流。

重点是：

- 当前阶段有没有留下足够证据
- 会不会把未解决的问题偷偷传给下一阶段

### 3.3 P0 门槛优先于排期

哪怕顺序都对，如果某一阶段还留着明确的 P0 风险，也不能假装它已经完成。

## 5. 阶段间硬门槛

下面这些门槛，不建议跳过：

- `M1 -> M2`：基线未盘清，不做视觉大改
- `M2 -> M3/M4/M5/M6`：设计系统未收口，不做核心页大改
- `M4/M5 -> M9`：主链路未成立，不做大规模联动
- `M10 -> M11`：后端与迁移未收口，不做正式对抗审查
- `M11 -> M12`：P0 未清零，不进发布

## 6. 一页判断法

后续如果只想快速判断“当前该不该进入下一阶段”，可以只看三件事：

1. 当前阶段的必须交付是否齐了
2. 当前阶段的退出门槛是否满足了
3. 推荐证据是否已经真实存在

只要有一项回答不清楚，就不算应该往下推进。
