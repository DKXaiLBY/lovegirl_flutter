## 3. 总体原则

### 3.1 投喂站优先保证“像真实叫单”

投喂站的核心不是商城式浏览，而是：

- 她点单时像真的在叫你买东西
- 你履约时像真的在处理一笔真实订单
- 最终交付过程有真实感、记录感、被照顾感

### 3.2 旅行地图优先保证“像真正地图产品”

旅行地图的核心不是做一张花哨页面，而是：

- 预览页有旅行气氛
- 真地图模式稳定
- 点位、路线、天气、花费、打卡、票根能在一个体系里讲通

### 3.3 功能链优先级高于细部装饰

这两块都不能先被视觉细节绑架。

优先级应当始终是：

1. 链路成立
2. 状态清晰
3. 中文干净
4. UI 精致
5. 动效增强

## 4. Wave 4：M4 投喂站重构

把投喂站从“功能很多但页面过重、前后端双轨、状态链不够真实”的页面，重构成一条完整的专属菜单体验链：

- 店铺成立
- 商品成立
- 下单成立
- 订单追踪成立
- 履约记录成立
- 爱心豆抵扣逻辑成立

只有满足下面这些条件，才建议进入 `M6 我的页`、`M7 Life 域收口` 和 `M8 Memory 域收口`：

## 8. 结论

LoveGirl 这次重构真正决定成败的，不是是否又多加了几个功能，而是：

- 投喂站能不能让人感觉“这是真的在叫你买东西”
- 旅行地图能不能让人感觉“这真的是你们的旅行工具”

这份执行包的价值，就是把这两条主线从“方向正确”推进到“能逐项施工、逐项验收”的状态。
