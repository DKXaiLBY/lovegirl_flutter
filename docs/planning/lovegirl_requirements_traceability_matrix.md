# LoveGirl 需求追踪矩阵

更新时间：2026-07-17
适用阶段：方案确认阶段（当前不写业务代码）

## 1. 文档目的

这份文档用来解决两个问题：

1. 这轮重构到底要交付哪些明确结果
2. 后面怎么证明这些结果是真的完成了

它不是新的方案，而是把现有方案拆成“可追踪、可验收、可核对”的清单。

## 2. 状态定义

- `planned`：已经确认要做，但还没进入实现
- `in_progress`：当前仓库已有部分成果，但还不能证明完成
- `done`：有明确实现和验收证据，当前阶段尚未大量出现
- `blocked`：依赖外部条件，当前阶段不使用

## 4. 当前阶段结论

截至 2026-07-17，当前阶段能证明的是：

- 需求已经被系统化整理
- 需求之间的依赖关系基本清楚
- 每一条需求未来该拿什么证据验收，已经定义

当前阶段还不能证明的是：

- 这些需求已经被全部实现
- 真机运行和服务端部署已经完成

所以这份文档的作用，是把“目标模糊的大项目”转成“后面可以逐条勾销的大项目”。

## 5. 后续使用方法

后面真正进入实现阶段时，建议这样用：

1. 每完成一个里程碑，更新对应需求状态
2. 每条 `in_progress` 或 `done` 的需求，都补上证据链接
3. 发布前必须逐条核对 `R-01` 到 `R-35`

没有证据的完成，不算完成。
