# LoveGirl 实施路线与验收清单

更新时间：2026-07-17
适用阶段：方案确认阶段（当前不写业务代码）

## 1. 目标拆解方式

这次不按“页面一个个随手改”推进，而是按可验收阶段推进。

每一阶段都要有：

- 交付内容
- 影响范围
- 风险点
- 验收标准

只有上一阶段过关，才进入下一阶段。

## 2. 总路线图

## 阶段 0：方案冻结

目标：

- 冻结产品方向
- 冻结保留 / 合并 / 删除清单
- 冻结 UI 母版方向
- 冻结高德地图方案

交付：

- 总方案文档
- 模块审计文档
- 实施与验收文档

验收：

- 后续开发不再反复推翻主方向

## 阶段 1：工程基线清理

目标：

- 先把“会拖慢一切的历史问题”控制住

内容：

- 清点乱码来源
- 清点重复模块
- 清点无效路由
- 清点旧搜索 / 卡路里残留
- 清点 Provider 与 Service 缺口

验收：

- 有清晰的重构范围表
- 有明确“不动什么、删什么、保留什么”

## 阶段 2：设计系统落地

目标：

- 把视觉基础件统一

内容：

- `LoveGirlTheme` 收口
- 统一色板
- 统一文字层级
- 统一卡片
- 统一按钮
- 统一标签
- 统一底部抽屉
- 统一空状态和加载态

验收：

- 核心页面不再各写各的风格
- 新页面可以直接复用基础组件

## 阶段 3：首页重构

目标：

- 首页尽量贴近确认参考图

内容：

- 顶部恋爱天数 / 天气 / 爱心豆
- 今日照顾卡
- 回忆票根
- 旅行票根
- 生活摘要
- 中文清理

风险点：

- 天气加载不稳定
- 体感温度溢出
- 图标风格不统一

验收：

- 首页第一屏气质正确
- 所有主要文案中文正常
- 天气卡不溢出

## 阶段 4：投喂站重构

目标：

- 从“商城页”改成“专属菜单”

内容：

- 店铺列表视觉统一
- 商品详情视觉统一
- 下单弹窗收口
- 订单状态链重做
- 爱心豆抵扣展示
- 男友端履约信息入口

风险点：

- 前后端状态字段不一致
- 真实平台记录缺字段
- 催单只加计数、不触发通知

验收：

- 女友端下单体验像真实叫单
- 男友端可以看懂并完成履约
- 订单流程文字、按钮、状态全部可读

## 阶段 5：旅行地图重构

目标：

- 彻底从旧瓦片方案切走

内容：

- 旅行预览页票根化
- 真地图模式切到高德原生 SDK
- 空状态引导
- 地点详情抽屉
- 地点归属标记
- 路线预览
- 天气 / 地址 / 交通信息

风险点：

- 打开真地图崩溃
- Key 或权限配置问题
- 真机定位与蓝点异常

验收：

- 真地图入口不崩
- 有地点时可以正常看点位
- 无地点时有中文引导
- 路线与详情结构成立

## 阶段 6：我的页重构

目标：

- 从功能清单改成关系资料夹

内容：

- 顶部关系摘要
- 爱心豆入口
- 伴侣绑定
- 通知 / 隐私 / 安全
- 数据 / 版本 / 更新

验收：

- 视觉语义不再像系统设置页
- 关键关系与账号信息一眼能看懂

## 阶段 7：生活域收口

目标：

- 让待办 / 愿望 / 记账 / 课程表成为一组稳定系统

内容：

- 待办与愿望共域
- 记账轻量化
- 课程表首页摘要
- 生活页入口重新排布

验收：

- 四个模块都能找到明确位置
- 首页能读到摘要

## 阶段 8：回忆域收口

目标：

- 把相册、纪念日、时光轴这些真正串起来

内容：

- 相册 / 照片合并
- 纪念日 / 倒数日合并
- 时间线沉淀
- 随机回忆
- 旅行小票能力预留

验收：

- 回忆资产不再分散
- 时间线开始具备“沉淀层”意义

## 阶段 9：联动与爱心豆

目标：

- 让模块之间真的开始互相工作

内容：

- 投喂 -> 记账
- 旅行 -> 记账
- 旅行 -> 时光轴
- 投喂 -> 时光轴
- 经期 -> 投喂推荐
- 首页摘要联动
- 爱心豆流水与抵扣逻辑

验收：

- 不再是孤岛模块
- 联动有来源、有归属、有展示

## 阶段 10：后端统一与数据库迁移

目标：

- 把前端所需的数据链真正补齐

内容：

- 数据表统一
- 迁移脚本整理
- 路由清理
- 删除废弃接口
- 高德 Web 服务后端代理
- 中文响应统一

验收：

- 前后端字段统一
- 核心链路不靠前端猜字段

## 阶段 11：对抗式审查

目标：

- 站在 QA 视角找问题

内容：

- 崩溃回归
- 权限回归
- 并发操作
- 推送失败一致性
- 爱心豆余额并发
- 文件清理
- 认证校验
- 上传校验
- Token 过期

验收：

- 形成 P0 / P1 / P2 审查报告
- P0 归零后才允许发布

## 阶段 12：真机验收与发布

目标：

- 确认不是“本地看起来能跑”，而是真的可以给你们用

内容：

- Android 真机装包验证
- 高德定位与蓝点
- 首页天气
- 投喂站流程
- 旅行地图流程
- 更新链路
- 服务器版本同步

验收：

- 真机核心流程通过
- 新版本号正确
- 服务器资源已替换
- 版本更新可用

## 3. 扩展性设计规则

为了以后新增功能方便，本轮实施时要强制遵守下面这些规则。

## 3.1 新前端功能接入规则

新增一个功能时，必须先回答：

1. 它属于哪个 domain？
2. 它的 model 是什么？
3. 它的 provider 是不是独立？
4. 它有没有首页摘要？
5. 它会不会联动到爱心豆、记账、时光轴？

只有答清楚再接入。

## 3.2 新后端功能接入规则

新增一个后端功能时，顺序固定为：

1. 设计表
2. 设计接口
3. 增加权限校验
4. 增加错误返回
5. 前端接入
6. 补验收点

## 3.3 新联动功能接入规则

联动只允许两种方式：

- 同步写入
- 异步事件触发

不能在多个页面里复制同一段联动逻辑。

## 4. 成功标准

## 4.1 方案阶段成功标准

当前这个阶段，成功标准不是“已经上线”，而是：

- 有一套完整主方案
- 有明确模块审计与去留
- 有实施路线图
- 有扩展规则
- 后续编码不再盲改

## 4.2 完整交付成功标准

最终完整成功，必须同时满足：

- UI 达到已确认方向
- 主要中文内容无乱码
- 旅行地图高德模式真机不崩
- 首页天气稳定
- 投喂站链路可走通
- 删除模块清理干净
- 联动链路成立
- 后端已部署
- 版本已正确发布

## 5. 当前阶段输出结论

本次方案阶段结束后，后续执行应该遵守一句话：

先按总结构收口，再逐域实施，再真机验收，最后才允许发布。
